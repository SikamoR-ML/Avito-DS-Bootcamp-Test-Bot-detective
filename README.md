# Определение автоматизированного трафика

Решение тестового задания: оценка для каждой `cookie_id` по событиям её
суточного окна. Основная метрика — максимальный Precision при Recall ≥ 70%.

## Состав репозитория

| Файл | Назначение |
| --- | --- |
| `solution.py` | Построение признаков, временная валидация, обучение и предсказание |
| `metric.py` | Официальная метрика из выданного задания |
| `submission.csv` | Готовые оценки для 4 909 куки из `test.csv` |
| `check_submission.py` | Независимая проверка формата и состава файла отправки |
| `requirements.txt` | Зафиксированные версии библиотек |
| `.gitignore` | Исключение исходных данных и локальных файлов из Git |

Исходные `train.csv`, `test.csv`, `events.csv.gz`, архив и quickstart не входят
в репозиторий. Для воспроизведения нужно положить выданные файлы в `data/`:

```text
data/
  train.csv
  test.csv
  events.csv.gz
```

## Запуск

Python 3.12.10. Из корня каталога с `data/train.csv`, `data/test.csv` и
`data/events.csv.gz`:

```bash
pip install -r requirements.txt
python solution.py
python check_submission.py
```

Скрипт создаёт `submission.csv` с одной оценкой от 0 до 1 для каждой куки из
`test.csv`. Случайность зафиксирована `random_state=2026`; использование
GPU, внешних API и больших языковых моделей не требуется.

## Подход

Сначала события связываются с куками и отбираются только при
`window_start_ts <= event_ts < window_end_ts`. События за пределами окна не
используются. На уровне куки рассчитываются 134 признака: количество событий
по типам, доли действий, число уникальных объявлений, запросов, категорий и
городов, концентрация этих значений, глубина поиска, последовательности
просмотров, интервалы между событиями, активность по часам, координаты
курсора, платформа, браузер и возраст куки. Идентификатор куки и абсолютная
дата окна в модель не подаются. Пропуски числовых признаков LightGBM
обрабатывает напрямую; категориальные признаки передаются как `category`.

Baseline — логистическая регрессия на возрасте куки, количестве событий,
уникальных объявлений и запросов, а также счётчиках событий. Улучшенное
решение — среднее оценок двух LightGBM с 15 и 31 листьями, ограничением
минимального числа наблюдений в листе и регуляризацией.

## Валидация

Поскольку тестовые окна относятся к более поздним датам, использовано
разделение по времени. Основной holdout: обучение 6–15 апреля 2026 года,
валидация 16–19 апреля. В нём 2 691 кука, включая 220 положительных.
Количество деревьев первой модели (274) выбрано ранней остановкой на этом
holdout; вторая использует 220 деревьев. Затем обе модели обучаются на всём
train и предсказывают test.

| Модель | Precision при Recall ≥ 70% | PR-AUC | ROC-AUC |
| --- | ---: | ---: | ---: |
| Логистическая регрессия, основной holdout | 0.16979 | 0.37208 | 0.77450 |
| LightGBM, основной holdout | 0.73585 | 0.78379 | 0.94315 |
| Ансамбль, основной holdout | 0.77778 | 0.78350 | 0.94311 |
| Ансамбль, 12–15 апреля¹ | 0.72470 | 0.76557 | 0.92171 |
| Ансамбль, 10–12 апреля² | 0.73516 | 0.75543 | 0.92022 |

¹ Обучение 6–11 апреля. ² Обучение 6–9 апреля. Независимый расчёт основной
метрики через `sklearn.metrics.precision_recall_curve` совпал с `metric.py`.
Выигрыш ансамбля на основном holdout нестабилен: бутстреп 95% интервала
разности его метрики и одиночной модели содержит ноль (−0.020; 0.059).
Эти результаты являются локальными оценками; качество на более позднем
скрытом тесте может отличаться из-за изменения трафика и состава сервисов.

Пробы с дополнительными признаками ритма и последовательного листания поиска
дали 0.739, 0.697 и 0.759 на трёх временных срезах соответственно. Из-за
просадки на среднем срезе они не добавлены в итоговую модель.

## Как оценки могут улучшить данные

На основном holdout порог, соответствующий лучшему локальному P@R70,
отмечает 154 из 220 куки положительного класса и 44 из 2471 куки
отрицательного класса. На уровне событий внутри тех же окон это 4811 из 5965
событий положительного класса и 1033 из 42667 событий отрицательного класса.
Следовательно, исключение отмеченных куки в этом локальном примере снижает
долю событий известного автоматизированного трафика с 12.27% до 2.70%, но
также исключает 2.42% событий отрицательного класса. Эти числа относятся
только к размеченной выборке: распространённость автоматизации в реальном
трафике может быть другой.

Практические применения: очищать метрики просмотров, поисков и контактов от
известного автоматизированного трафика; снижать его влияние на обучающие
данные рекомендательных и поисковых моделей; направлять куки с высокими
оценками на дополнительную проверку. Автоматическое удаление или блокировка
требует отдельной проверки ложных срабатываний. Score ансамбля ранжирует
куки, но не калиброван как вероятность. Разметка охватывает известные сервисы
сбора данных, поэтому качество на новых типах ботов ещё не измерено.

Использованы локальные open-source библиотеки NumPy, pandas, scikit-learn и
LightGBM. Внешние API и предобученные модели не применялись.
