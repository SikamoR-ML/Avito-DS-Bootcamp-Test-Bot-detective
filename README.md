# Детекция автоматизированного трафика Авито

Модель присваивает каждой `cookie_id` оценку `score` от 0 до 1 по событиям внутри суточного окна. Чем выше score, тем вероятнее, что cookie относится к трафику известных сервисов сбора данных. Готовый ответ: `submission.csv`.

## Данные и метрика

Файлы `data/train.csv` и `data/test.csv` содержат `cookie_id`, время создания cookie и границы окна. В `train.csv` также есть `target`: 1 для известных сервисов сбора данных, 0 для трафика, отнесённого к человеческому. `data/events.csv.gz` содержит действия, объявления, поисковые запросы, User-Agent и координаты курсора. Исходные данные в Git не публикуются.

Основная метрика: максимальный **Precision при Recall >= 0.70** по cookie. Проверяются все пороги; одинаковые score обрабатываются одной группой. Порог в ответ передавать не нужно. PR-AUC и ROC-AUC используются только для диагностики.

## Решение

Признаки строятся только из событий с `window_start_ts <= event_ts < window_end_ts`. 134 базовых признака описывают объём активности, объявления и запросы, категории, глубину поиска, интервалы и переходы между событиями, курсор, платформу и возраст cookie. Ещё 12 признаков описывают User-Agent и форму запросов. Пропуски числовых признаков обрабатывают модели; категориальные уровни и порядок колонок сохраняются в `artifacts/feature_schema.json`. `cookie_id` и абсолютная дата окна не используются как признаки.

Итоговый score: 40% ансамбля из двух LightGBM и CatBoost на базовых признаках плюс 60% такого же ансамбля с 12 дополнительными признаками. Случайность зафиксирована: `random_state=2026`. Используются локальные open-source NumPy, pandas, scikit-learn, LightGBM и CatBoost с точными версиями в `requirements.txt`. Внешние API и большие языковые модели не применялись.

Обучение на ранних датах и проверка на последующих выполнены на четырёх forward temporal folds, в том числе на семидневном горизонте. Средний P@R70 итоговой модели равен **0.76355**, худший fold **0.73522**. XGBRanker и TabM отдельно проверены на тех же folds; подтверждённого прироста среднего результата не дали и не входят в финальную модель. Подробности и TP/FP приведены в `RESEARCH.md`.

## Файлы и запуск

- `solution.py`, `extra_features.py`: признаки, обучение и создание `submission.csv`.
- `predict.py`: предсказание из сохранённых моделей без переобучения.
- `validate.py`, `metric.py`: временная проверка и официальная метрика.
- `artifacts/`: шесть моделей и схема признаков для inference.
- `BASELINE.md`, `RESEARCH.md`: исходный результат и краткий отчёт об экспериментах.

Python 3.12.10. Разместите выданные `train.csv`, `test.csv`, `events.csv.gz` в `data/`, затем выполните:

```bash
python -m pip install -r requirements.txt
python solution.py
python predict.py
python validate.py
```

`solution.py` обучает модель на полном train и создаёт ответ. `predict.py` повторно создаёт тот же ответ из `artifacts/`, без train. `validate.py` воспроизводит четыре временных сравнения.

Файл ответа содержит ровно 4909 строк и только `cookie_id,score`, без пропусков и повторов, в порядке `data/test.csv`. Скрытая метрика финального ответа пока неизвестна. Разметка отражает известные источники трафика; качество на новых типах автоматизации может отличаться от локальной оценки.
