# Детекция автоматизированного трафика Авито

Решение присваивает каждой `cookie_id` оценку `score` от 0 до 1 по событиям суточного окна. Чем выше оценка, тем вероятнее принадлежность к трафику известных сервисов сбора данных.

## Файлы

- `submission.csv`: готовые предсказания для 4 909 куки из `data/test.csv`.
- `solution.py`: признаки, baseline, временная валидация, обучение и сохранение моделей.
- `predict.py`: предсказание из сохранённых моделей без переобучения.
- `artifacts/`: две модели LightGBM в формате `.txt`, модель CatBoost в формате `.cbm` и `feature_schema.json`.
- `metric.py`: метрика, предоставленная в задании.
- `requirements.txt`: зафиксированные версии библиотек.

## Запуск

Python 3.12.10. Выданные `train.csv`, `test.csv` и `events.csv.gz` нужно разместить в папке `data/`. Исходные данные не включены в репозиторий.

```bash
pip install -r requirements.txt
python solution.py
```

Скрипт обучает модели и создаёт `submission.csv`. Для повторного предсказания из готовых моделей без `train.csv`:

```bash
python predict.py
```

Оба способа дали одинаковые оценки для всех 4 909 тестовых куки. Файл ответа содержит только `cookie_id,score`, без пропусков и повторов `cookie_id`.

## Подход

Используются только события с `window_start_ts <= event_ts < window_end_ts`. Построены 134 признака: счётчики и доли типов событий, уникальные объявления, запросы, категории и локации, глубина поиска, переходы между событиями, интервалы и часы активности, координаты курсора, платформа, браузер и возраст куки. `cookie_id` и абсолютная дата окна не подаются в модель.

Пропуски числовых признаков обрабатывают модели. Категориальные значения нормализуются, а порядок признаков и уровни категорий сохранены в `feature_schema.json`. Дубликаты событий оставлены в исходном потоке: удаление точных дублей ухудшило метрику на двух временных срезах.

Baseline: логистическая регрессия на возрасте куки, объёме активности и счётчиках событий. Итоговая оценка: 35% LightGBM с 15 листьями, 35% LightGBM с 31 листьями и 30% CatBoost. Проверяли дополнительные признаки ритма и последовательного листания поиска; устойчивого выигрыша они не дали.

## Валидация

Основной временной срез: обучение на 6-15 апреля 2026 года, проверка на 16-19 апреля. В проверке 2 691 кука, включая 220 положительных. Метрика рассчитана по `cookie_id` с группировкой одинаковых оценок.

| Модель | Precision при Recall >= 70% | PR-AUC |
| --- | ---: | ---: |
| Baseline | 0.16979 | 0.37208 |
| Две LightGBM | 0.77778 | 0.78350 |
| CatBoost | 0.77889 | 0.78754 |
| Итоговая смесь | 0.77500 | 0.78974 |

На двух более ранних временных срезах итоговая смесь дала 0.76555 и 0.74274 по основной метрике. Для двух LightGBM соответствующие результаты были 0.73516 и 0.72470. Смесь выбрана за более ровный результат во времени; основной срез использовался при выборе модели и может быть оптимистичным для скрытого теста. Разметка охватывает известные сервисы сбора данных; качество на новых типах ботов не измерено.

Использованы локальные open-source библиотеки NumPy, pandas, scikit-learn, LightGBM и CatBoost. Внешние API, большие языковые модели, ручная разметка теста и правила для отдельных `cookie_id` не применялись. Случайность зафиксирована `random_state=2026`.
